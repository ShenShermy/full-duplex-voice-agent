# 04 排错与调参

> 这篇文章回答两类问题：**跑不起来怎么办**、**效果不好怎么调**。
> 所有参数都在 `config.yaml`，改完不用改代码。

---

## 一、先跑体检

任何时候出问题，第一步都是：

```powershell
python setup\verify_env.py
```

它会检查六件事，并把问题写成"人话 + 修复命令"：

| 检查项 | 常见输出 |
|---|---|
| Python 版本 | `[X] 需要 3.10~3.12，当前 3.13` |
| 依赖包 | `[!] 缺 sounddevice —— pip install sounddevice` |
| torch + CUDA | `[!] torch 是 CPU 版，CUDA 不可用` |
| 音频设备 | `[!] 没找到输入设备` |
| 模型文件 | `[!] 模型目录不存在：models\paraformer-zh` |
| 配置 + API key | `[!] 没设环境变量 DEEPSEEK_API_KEY` |

## 二、常见故障速查表

### 装不上 / 起不来

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: numpy` | 没进 venv | `.venv\Scripts\activate` 再跑 |
| `pip` 卡住 / SSL 错误 | 网络到 PyPI 不通 | 用镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| `torch` 装了但没有 CUDA | 装成 CPU 版了 | `pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121` |
| `ImportError: DLL load failed` | 缺 VC++ 运行库 | 装 [VC++ 2015-2022 Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
| `miniyaml` 解析报错 | 配置里用了不支持的 YAML 语法 | 只支持：嵌套映射、`- ` 列表、`[a, b]`、`\|`/`>` 块文本、注释；或用 pyyaml |
| `python: can't open file 'run.py'` | 不在项目根目录 | `cd full-duplex-voice-agent` 再跑 |

### 声音 / 麦克风

| 现象 | 原因 | 解决 |
|---|---|---|
| `sounddevice` 报 `PortAudioError` | 没有默认输入设备 | `python run.py --list-devices` 看设备号，填 `audio.mic_device` |
| 有设备但录不到声音 | Windows 隐私设置 | 设置 → 隐私和安全性 → 麦克风 → 允许桌面应用访问 |
| 没有声音输出 | 输出设备错了 | `audio.speaker_device` 填设备号 |
| 声音很小 | 系统音量 / 增益 | `audio.speaker_volume: 1.2`、`audio.mic_gain: 1.5` |
| 爆音、噼啪声 | 采样率不匹配或没淡入淡出 | 保持 `sample_rate: 16000`；真 TTS 输出 24k 要重采样（已自动做） |

### 打断相关（这是重灾区）

| 现象 | 原因 | 解决 |
|---|---|---|
| **完全不打断** | VAD 完全没检出语音 | 先看日志有没有 `barge_in_detected`；没有就调低 `vad.energy_threshold`（0.015 → 0.008） |
| 播报时插话没反应 | 回声门控太严 | `vad.echo_gate.threshold_ratio` 2.5 → 1.8 |
| 机器人自己打断自己 | 回声门控没生效 | 检查 `_on_bot_start` 是否被调用；或 `threshold_ratio` 调到 3.0 |
| 稍微出点声就断 | `barge_in.min_speech_ms` 太小 | 240 → 320 |
| 打断后声音停不下来 | 播放线程没收到代数变化 | 看 `bot_audio_stopped` 有没有打；`flush` 的 `last_flush_ms` 是否接近 300（=超时了） |
| 打断后机器人"忘了说过什么" | 历史截断过头 | 检查 `played_text` 是否返回空；`fraction` 是不是太小 |

### 对话质量

| 现象 | 原因 | 解决 |
|---|---|---|
| 回答太长，说半天 | prompt 没生效 | 看 `llm.system_prompt` 是否被覆盖；`max_tokens` 调小到 120 |
| 断句怪，一顿一顿的 | 软断点切太碎 | `SentenceSplitter` 的 `soft_min_len` 12 → 20 |
| 上一轮的话被重复回答 | 历史里有重复的 assistant | 检查打断分支是否写了两次 |
| 说到一半忘了上下文 | `max_turns` 太小 | 6 → 8；或 `max_chars` 1200 → 2000 |

## 三、关键参数怎么调（带原理）

### VAD 三兄弟

```yaml
vad:
  energy_threshold: 0.015      # ★ 最重要的一个
  min_speech_ms: 160
  silence_ms: 500
```

| 参数 | 调大 | 调小 |
|---|---|---|
| `energy_threshold` | 更抗噪，但小声说话检测不到 | 更灵敏，但噪音会误触发 |
| `min_speech_ms` | 更不容易被"咔哒"声触发 | 反应更快，但容易切碎 |
| `silence_ms` | 用户停顿不会被打断（适合思考型说话） | 判定"说完了"更快，但容易在句中截断 |

**怎么定**：先跑一次，看日志里 `user_speech_start` 是否在你开口后约 160ms 出现；
如果噪音导致频繁误触发，把 `energy_threshold` 加 50%。

### 打断确认

```yaml
barge_in:
  min_speech_ms: 240    # 必须 > vad.min_speech_ms
```

实际上算法是：VAD 起始已经要 160ms，打断再额外等 `240-160=80ms`。
**这两个数字故意分开**：VAD 的灵敏度是为"开始录音"调的，打断的是为"打断"调的。
误打断比漏打断的代价大得多（一个突然闭嘴的机器人很吓人）。

### TTS 延迟

```yaml
tts:
  backend: silent            # silent 最稳定；pyttsx3 有声音；cosyvoice 最好听
  cosyvoice:
    stream: true             # ★ 一定开，chunk 级流式
```

如果 `tts_latency` 高，先看是不是"攒句等待"——把 `SentenceSplitter` 的 `soft_min_len` 调小
（12 → 8）会让出音更早，但语调更碎。

### 20ms 这个数

```yaml
audio:
  block_ms: 20
```

- 太小（5ms）：Python 层回调开销大，CPU 空转
- 太大（100ms）：打断最坏要等 100ms 才停，用户能听出"多出来的话"

20ms 是 WebRTC 的默认音频帧长，也是我们的平衡点。

## 四、换真模型的步骤

### 方案 A：LLM 走 API（推荐，8G 也能跑）

```powershell
$env:DEEPSEEK_API_KEY = "sk-xxxx"
```

```yaml
llm:
  backend: openai_compat
  openai_compat:
    base_url: https://api.deepseek.com/v1
    model: deepseek-chat
```

任何 OpenAI 兼容端点都行：DeepSeek、Moonshot、vLLM、ollama、OneAPI。
**注意**：`ollama` 的 `/v1` 路径如果是 `http://localhost:11434/v1`，`api_key` 随便填。

### 方案 B：ASR 换 FunASR

```powershell
python setup\download_models.py --only asr
python setup\download_models.py --only vad
python setup\download_models.py --only punc
```

```yaml
asr:
  backend: funasr
  funasr:
    model: iic/speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-pytorch
    vad_model: iic/speech_fsmn_vad_zh-cn-16k-common-pytorch
    punc_model: iic/punc_ct-transformer_zh-cn-common-vocab272727-pytorch
    device: cuda
```

### 方案 C：TTS 换 CosyVoice2

```powershell
powershell -ExecutionPolicy Bypass -File setup\install_cosyvoice.ps1
```

```yaml
tts:
  backend: cosyvoice
  cosyvoice:
    model_path: models/CosyVoice2-0.5B
    device: cuda
```

`src/tts.py` 会自动把 `third_party/CosyVoice` 加进 `sys.path`，不用设 `PYTHONPATH`。

### 8G 显存账本（很实用，面试可以讲）

| 组件 | 显存 |
|---|---|
| FunASR Paraformer + VAD + 标点 | ≈ 1.5 GB |
| CosyVoice2-0.5B | ≈ 1.6 GB |
| Qwen2.5-7B AWQ 4bit | ≈ 5.0 GB |
| **合计** | **≈ 8.1 GB** ← 4060 Ti 是 8G，**会爆** |

所以默认配置是"本地 ASR/TTS + API LLM"（占 3.1G，安全）。
要全本地就把 LLM 换成 1.5B/3B，质量掉但能跑。

## 五、跟 pipecat / LiveKit 的对照

如果你面试被问"知道 pipecat 吗"，这张表能救你：

| 能力 | 本项目 | pipecat | LiveKit Agents |
|---|---|---|---|
| 传输层 | 本地麦克风/扬声器 | 抽象 transport（本地/WebRTC/WebSocket） | WebRTC（房间模型） |
| 管线组织 | 手写状态机 + 三线程 | `Pipeline` + `FrameProcessor` 链 | `AgentSession` + `voice` 管线 |
| 打断 | 自研（代数 + 队列清空） | 内置 `allow_interruptions` | 内置 turn detection |
| VAD | 能量 / Silero | Silero + 可插拔 | 内置 |
| 延迟观测 | 自研九事件 + 六指标 | `enable_metrics` | 内置 metrics |
| 依赖体量 | numpy + yaml（核心）/ torch（真模型） | 中等，版本变动快 | 较大（含 WebRTC） |
| 适合 | 学习、单机 demo、嵌入式 | 快速搭服务 | 多人房间、生产 |

**怎么讲**：
> "我看过 pipecat 的组织方式，它的 `FrameProcessor` 链比我的手写状态机更可扩展，
> LiveKit 的 turn detection 比我的 240ms 阈值更聪明。我选择自己写是为了搞清每一行，
> 迁到 pipecat 对我来说是把 `vad.process()` 换成一个 frame processor，逻辑是通的。"

## 六、复现我们的实测数据

```powershell
cd full-duplex-voice-agent
python run.py --backend mock --max-turns 4
```

应该看到（数字会有小幅波动）：

```
[e2e] 轮次=4  打断=3 (75%)
     asr_latency      116 ms  (p90 130)   预算 300  ✓
     llm_ttft          17 ms  (p90  22)   预算 400  ✓
     tts_latency      151 ms  (p90 185)   预算 300  ✓
     e2e_first_audio  283 ms  (p90 310)   预算 800  ✓
     barge_in_stop     14 ms  (p90  19)   预算 250  ✓
```

**如果打断次数是 0**，说明 VAD 有问题，看第二节的"完全不打断"。

**如果 `barge_in_stop` 接近 300**，说明 `flush()` 在等超时——检查 `_pump` 里
"写失败"分支有没有 `self._interrupted.set()`。
